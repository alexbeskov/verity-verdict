# Verity Verdict — AI Due Diligence

Verity Verdict — ИИ-инструмент для автоматизированной проверки контрагентов и целей инвестиций (due diligence). Система анализирует пакет документов компании и возвращает риск-балл, красные флаги с цитатами из источников, противоречия между документами, вопросы для встречи с собственником и резюме для инвестиционного комитета.

> **Это MVP-демо на синтетических данных вымышленной компании.** Результаты формируются ИИ и требуют проверки аналитиком.

## Запуск локально

```bash
# 1. Установить зависимости
npm install

# 2. Создать файл окружения
cp .env.example .env.local

# 3. Вписать ключ Polza.ai в .env.local
# Получить ключ: https://polza.ai — Личный кабинет → API

# 4. Запустить
npm run dev
```

Откройте http://localhost:3000

## AI-провайдер

Проект использует [Polza.ai](https://polza.ai) — OpenAI-совместимый API-прокси.

**Модели (цепочка с фоллбэком):**
1. `deepseek/deepseek-v4-flash` — основная (~5.7₽/1M prompt, ~11.4₽/1M completion)
2. `deepseek/deepseek-v4.1-flash` — резервная
3. `google/gemma-4-26b-a4b-it` — запасная

Один анализ расходует ~2K prompt + ~2K completion токенов ≈ **0.03–0.05₽ за прогон**.

## Деплой на Vercel

1. Залейте репозиторий на GitHub
2. В Vercel: Import Project → выберите репозиторий
3. В Settings → Environment Variables добавьте: `POLZA_API_KEY` = ваш ключ
4. Deploy

Платных доменов подключать не нужно — работает на `*.vercel.app`.

## Режим «Записанный прогон»

На случай, если модель недоступна во время демонстрации, предусмотрен режим записанного прогона. Включите чекбокс «Записанный прогон» на экране загрузки — система покажет заранее сохранённый результат анализа с имитацией живого лога шагов. API-ключ для этого режима не требуется.

## Стек

- Next.js (App Router) + TypeScript + Tailwind CSS
- Polza.ai (DeepSeek V4 Flash)
- Хостинг: Vercel Hobby (бесплатный план)

## Безопасность

- Ключ Polza.ai хранится только в серверной переменной окружения
- На клиент ключ не попадает ни при каких условиях
- Содержимое документов не логируется

## Ограничения MVP

- Только текстовый ввод (нет загрузки PDF/DOCX)
- Нет авторизации и истории проверок

> **Для реальных клиентов необходимо:** развёртывание в контуре клиента (on-premise), платные модели с гарантией неиспользования данных для обучения, интеграция с реальными источниками данных.

## Идеи для доработки

1. **Реальные источники данных**: ЕГРЮЛ, арбитражные суды, ФНС, реестры залогов
2. **Загрузка PDF/DOCX**: парсинг документов с сохранением структуры
3. **История проверок**: база данных, сравнение результатов во времени
4. **Роли и команды**: аналитик, руководитель, комитет — с разными уровнями доступа
5. **On-premise развёртывание**: Docker-образ с поддержкой локальных LLM через Ollama или vLLM
